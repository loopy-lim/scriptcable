# .so 배치 실행기 + 라우팅 교정 + 업스트림 요구 문서 — 2026-10-25

## 요구 (전 라운드 recommendations의 실행)

1. **.so 배치 TU** — 호스트 공유 라이브러리에 plain C 배치 실행기(`scriptc_batch`)를 링크해
   koffi/Windows(애드온 부재 티어)에 배치 가속 제공. android는 제외(버전맵·selective pulling).
2. **Bun 숫자 배치 라우팅 교정** — 배치 라운드 실측에서 발견: Bun에서 숫자 위주 배치를 애드온
   실행기로 돌리면 43.6ns/op인데 ffi 직결 루프는 16ns/op — 구성(composition)에 따른 라우팅 필요.
3. **BATCH_WASM check 균일화** — wasm 플레이버 폴백이 단일 호출(`mod.call`)과 동일 오류/동작.
4. **scriptc 업스트림 요구 문서** — 경계 내 배치 프리미티브·입력 zero-copy/arena·export 테이블
   디스패치, 실측 근거와 와이어 스펙 제안 포함.
5. **커밋/푸시** — 권한 경계. 질문 1회(커밋+푸시 / 커밋만 / 안 함, 기본 안 함) — 완료 시 적용.

**범위 밖**: wasm 경계 내 배치(업스트림), 애드온 실행기 변경(완료됨), Node CI 실측 수치(푸시 후).

## 조사 결과 (근거 — 2026-10-25 프로브 실측)

- **bun:ffi dlopen은 누락 심볼이 있으면 throw**(`Symbol "missing" not found`)하고, 실패 후
  동일 .so를 축소 심볼표로 재 dlopen하면 정상(재시도 프로브 — exists(21)=42n). → 2단 감지.
  i64 반환은 BigInt(42n) — Number() 변환 필요.
- **koffi `_Out_ void**`·int64 반환(number)·`koffi.decode`는 복사본**(오버라이트 후에도
  stable) — 프로브로 확인. makeKoffiFunc의 기존 `_Out_` 패턴과 동일.
- **link-shared `extraSources`**는 android JNI 접착용으로 이미 호스트·크로스 모두 지원
  (toolchain.ts:429) — TU 추가는 같은 경로. android는 selective pulling + `Java_*` 전용
  버전맵이라 실행기 심볼이 localized돼 무용+위험 → 제외.
- **`makeKoffiFunc`/`bindKoffiSync`**는 내부 함수 — koffi 배치 테스트를 위해 export 필요.
- **전 라운드 실측**(batch 라운드): 애드온 실행기 숫자 43.6ns/op vs bun:ffi 직결 단일 16ns/op
  → Bun 숫자는 루프가 이김. koffi 숫자 단일 ~600ns급 → koffi는 숫자도 실행기가 이김.
  문자열은 실행기·와이어가 양쪽에서 이김(ffi 마샬링 루프 1.2µs vs ~0.88µs).
- **wasm BATCH_WASM**: fns 직접 루프라 unknown export가 TypeError — `mod.call` 경유하면
  로더 배치·단일 호출과 동일 ScriptcableError(불러올 코드젠 import 없음 — 브라우저 그래프
  제약 회피).
- **코어 테스트 관례**: addon-batch.test.ts가 native.c→ar→buildNodeAddon 테스트 시점 컴파일;
  linkSharedLibrary도 export돼 있어 같은 방식으로 TU 포함 .so를 테스트 가능.

## 설계 결정

1. **D1 심볼 고정명 `scriptc_batch`** + 코드젠 가드 — 어떤 export symbol과도 같으면 TU 자체를
   생략(F-2 교훈의 재적용: rename이 아닌 가드가 완전한 울타리). exports 0개여도 생략.
2. **D2 TU C 계약**: `int64_t scriptc_batch(const int32_t* meta, int64_t meta_elems,
   const uint8_t* args, int64_t args_len, uint8_t** out_block)` — 양수=결과 블록 바이트 수,
   -1 와이어 오류, -2 경계 위반, -3 OOM. 결과 블록은 `_Thread_local` grow-only(F-1 교훈),
   **유효기한 = 같은 스레드의 다음 배치까지** — JS는 decode로 즉시 소진(복사).
3. **D3 2단 dlopen 감지**(bun:ffi) — 배치 심볼 포함 시도 → throw 시 축소 심볼표 재시도.
   koffi는 dlopen이 심볼 확인을 늦게 하므로 typeof 검사.
4. **D4 라우팅(구성 인지)**:
   - 로더(NativeModule.batch): 실행기 링크 + (마샬링 export 포함 OR koffi) → 실행기,
     bun:ffi + 숫자 전용 → 순차 루프(16ns/op 유지). `batchTransport` capability 노출
     ('executive' = 링크됨).
   - 클라이언트 shared 플레이버: 애드온 실행기 && (!IS_BUN || 마샬링 포함) → 애드온 실행기,
     그 외 → `mod.batch`(로더 라우팅 위임). Node direct 플레이버: 애드온 실행기 항상(기존).
5. **D5 BATCH_WASM → `mod.call` 루프** — 단일 호출과 오류·동작 완전 균일(폴백 성능 불문).
6. **D6 android TU 제외** — toolchain이 non-android 호스트 링크에만 extraSources 추가.
7. **D7 koffi 테스트는 `bindKoffiSync` export로** (로컬 bun에서 강제 바인딩), 전달 경로의
   koffi 실런타임은 CI bench-node가 담당.
8. **D8 업스트림 문서는 연구 문서로** — scriptc 관리 주체와 무관하게 이슈/제안 재료로 쓰게
   측정·스펙·설계 스케치를 독립 파일로.

## 가정 로그

- **라우팅 규칙의 koffi/ffi 비대칭**: bun:ffi 숫자 직결이 세상에서 가장 빠른 경로라 숫자 전용
  배치는 루프가 정답이지만, koffi는 그 반대 — 바인딩이 `loopFastNumbers` 플래그를 갖는 이유.
- **.so 실행기 미측정 기대치 미선언**: koffi 문자열 절반 가까이 감소 추정은 측정 전 가정 —
  AC-5 실측으로 확정하며 임계 선언 없음.
- **Bun 마샬링 배치는 애드온 실행기 유지**(측정된 883ns 경로) — ffi 실행기가 더 빠를 가능성은
  bench 행 비교로만 관찰, 자동 전환하지 않음(측정 근거 생기면 후속).
- **커밋/푸시**: 질문 1회, 기본 안 함 — Node 실측 AC는 푸시 전까지 BLOCKED 유지(전 라운드와 동일).
